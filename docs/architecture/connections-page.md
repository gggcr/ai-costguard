# Страница «Подключённые системы»: что нужно от фронтенда

Задание для фронтенд-команды. Код в `apps/frontend` не менялся, кроме сгенерированных типов
`src/api/generated/core.ts` (`make codegen`): там уже есть `Connection`, `ConnectionDetails`, `ConnectionRun`,
`SystemType`. API описан в `schemas/openapi/core.yaml`, тег `Connections`; устройство — в ADR 0019.

## Доступ

- Новый раздел `connections`, маршруты `/connections` и `/connections/:id`, пункт меню «Подключения» рядом с
  «Импортом».
- Видят: `owner`, `it_admin`, `finance`, `auditor` (API отдаёт список любому пользователю компании, раздел в
  меню — решение команды).
- Меняют: только `owner` и `it_admin` (`EDIT` в `auth.tsx`). Остальным кнопки «Подключить», «Отключить»,
  «Синхронизировать» не показывать. Если сервер всё равно ответил 403 `role_required`, показать текст ошибки.

## Экран 1. Список систем — `/connections`

Данные: `GET /api/v1/connections` → `Connection[]`. Обновлять раз в 30 секунд, пока хотя бы одна система в статусе
`sync_requested` или `pending`, иначе при возврате на вкладку.

Таблица, по строке на систему:

| Колонка | Поле | Как показать |
|---|---|---|
| Система | `name`, под ним название типа | Название типа из `GET /types` (`title`) по `type`; группировать или фильтровать по `kind` (учёт, кадры, учётные записи, техника, банк, почта) |
| Статус | `status` | Бейдж: `connected` — «Работает», `failing` — «Ошибка», `pending` — «Ждёт первой выгрузки», `sync_requested` — «Синхронизация запрошена», `disconnected` — «Отключена» (серый) |
| Последняя синхронизация | `lastSyncAt` | Относительное время («12 минут назад»), полная дата в подсказке; `null` — «ещё не было» |
| Записей | `recordsLastSync`, `recordsTotal` | «120 за последнюю, 4 380 всего»; `null` — «—» |
| Последняя ошибка | `lastError`, `lastErrorAt` | Первая строка ошибки и время, полный текст в подсказке или на экране 2. Для `connected` с ошибкой в прошлом — приглушённо |
| Управление | `managedInCore` | `false` — пометка «Настроено в файле агента»: настройки в ядре неизвестны, подключение из ядра заберёт управление |
| Действия | — | «Синхронизировать» (только не `disconnected`), «Отключить», для `disconnected` — «Подключить снова» |

Кнопка «Подключить систему» над таблицей открывает экран 3.

Пустое состояние: «Пока ничего не подключено» и кнопка «Подключить систему».

## Экран 2. Система — `/connections/:id`

- `GET /api/v1/connections/{id}` — карточка: все поля экрана 1, настройки (`settings`, ключ → значение,
  только чтение), когда подключена (`createdAt`), когда запрошена синхронизация (`syncRequestedAt`).
- `GET /api/v1/connections/{id}/runs` — последние 20 выгрузок: начало, длительность (`finishedAt - startedAt`),
  статус `SUCCEEDED`/`FAILED`, `records`, `error` целиком (моноширинным шрифтом, с переносом строк).
- Блок «Что нужно агенту»: из `GET /types` для этого типа — список `secrets` с пояснением, что их задают в
  окружении агента коннекторов или в Vault, а не на этой странице. Если последняя ошибка начинается с
  `Missing setting or secret`, выделить этот блок.
- Действия те же, что в строке списка.

## Экран 3. Подключение — модальное окно или `/connections/new`

1. Выбор типа: карточки из `GET /api/v1/connections/types` (`title`, сгруппировать по `kind`). Типы, которые уже
   подключены и включены (`managedInCore = true`), неактивны с подписью «Уже подключено».
2. Форма:
   - «Название» (`name`, обязательно, до 120 символов, по умолчанию `title` типа);
   - поле на каждый ключ из `required` (обязательные) и `optional`. Подписи по ключу: `url` — «Адрес»,
     `user` — «Пользователь», `org_id` — «ID организации», `directory_id` — «ID каталога (tenant)»,
     `client_id` — «ID приложения», `admin` — «Администратор», `customer` — «ID клиента Google»,
     `host` — «IMAP-сервер», `folder` — «Папка», `accounts` и `ignore` — список через запятую,
     `min_image_kb` и `min_image_side` — числа;
   - секретов в форме нет: под формой список `secrets` с текстом «Задайте в окружении агента».
3. `POST /api/v1/connections` с `{ type, name, settings }`. Ответ 201 — новая система, 200 — подключена снова
   (та же `id`). Перейти на экран 2.

## Действия

| Действие | Запрос | Ответ | После |
|---|---|---|---|
| Синхронизировать | `POST /api/v1/connections/{id}/sync` | 202 и `Connection` со статусом `sync_requested` | Обновить строку. Подсказка: агент в сети клиента начнёт в течение минуты, агент в Airflow — в следующий час |
| Отключить | `DELETE /api/v1/connections/{id}` | 204 | Подтверждение «Агент перестанет выгружать систему, история останется». Повторное отключение тоже 204 |
| Подключить снова | `POST /api/v1/connections` с типом и настройками | 200 | Форма экрана 3 с заполненными `settings` |

## Ошибки (RFC 9457, поле `code`)

| `code` | HTTP | Что показать |
|---|---|---|
| `role_required` | 403 | «Менять подключения могут владелец и ИТ-администратор» |
| `connection_not_found` | 404 | Экран «Система не найдена», ссылка на список |
| `unknown_system_type` | 400 | «Этот тип систем агент не поддерживает» |
| `setting_missing` | 400 | Подсветить пустые обязательные поля |
| `setting_unknown` | 400 | «Лишнее поле. Секреты задаются в окружении агента» |
| `already_connected` | 409 | «Система уже подключена», ссылка на неё |
| `not_connected` | 409 | «Система отключена, подключите её снова» |

## Демо-режим

Фронтенд сейчас работает на `api/mock-data.ts`. Для демо нужны выдуманные подключения во всех статусах
(например: 1С — `connected`, Okta — `failing` с ошибкой `401 Unauthorized`, Т-Банк — `pending`, Jamf —
`disconnected`, МойСклад — `managedInCore = false`).
