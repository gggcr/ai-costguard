# SCIM: сотрудники из identity-провайдера

CostGuard работает как SCIM 2.0-сервер (ADR 0043). Identity-провайдер компании сам создаёт, меняет и отключает в нём
сотрудников: Okta, Entra ID, Keycloak (через расширение), OneLogin, JumpCloud.

## Подключить

1. Владелец или ИТ-администратор выпускает токен:
   `POST /api/v1/scim/tokens` с телом `{"name": "Okta", "dismissOnDeactivate": true}`.
   Токен (`cgscim_…`) приходит в ответе один раз. Сохраните его сразу.
2. В провайдере:
   - базовый URL — `https://<адрес CostGuard>/scim/v2`;
   - аутентификация — HTTP Header / Bearer Token, значение — этот токен.
3. Включите в провайдере создание, изменение и деактивацию пользователей. Группы CostGuard не нужны.

Провайдер сначала ищет каждого человека по `userName eq "…"`. У сотрудников, заведённых в CostGuard руками,
userName — это их почта. Поэтому провайдер, у которого userName тоже почта (так бывает почти всегда), находит их и не
создаёт двойников. Если в POST /Users пришла почта сотрудника, которого провайдер ещё не вёл, этот сотрудник
переходит под провайдера.

## Что во что превращается

| От провайдера | В CostGuard |
|---|---|
| `name.formatted`, иначе «Фамилия Имя Отчество» из частей, иначе `displayName` | ФИО |
| основной `emails`, иначе `userName`, если это почта | почта |
| `title` | должность (без неё — «Сотрудник») |
| `department` расширения EnterpriseUser | отдел по имени; нет такого — создаётся; не задан — «Без отдела» |
| `active: false` | при `dismissOnDeactivate` — увольнение, иначе только пометка в SCIM |
| DELETE | увольнение; сотрудник остаётся в истории |

Увольнение по SCIM работает так же, как увольнение руками:
- запускает чек-лист;
- создаёт находки по лицензиям и технике;
- пишется в журнал действий от имени `scim`.

`active: true` не возвращает уволенного сотрудника: повторный приём на работу решает человек.

## Отозвать токен

`DELETE /api/v1/scim/tokens/{id}` — запросы с этим токеном получают 401 сразу. Когда токен последний раз
использовался, показывает `lastUsedAt` в `GET /api/v1/scim/tokens`.

## Если не работает

- **401** — токен отозван, набран с ошибкой или передан не как `Bearer`.
- **409 uniqueness** — у другого пользователя уже такие userName или почта.
- **403** — компания упёрлась в лимит сотрудников тарифа.
- **400 invalidFilter** — провайдер прислал фильтр сложнее `attribute eq "value"`. Такие фильтры не поддерживаются.
- Ссылки `meta.location` с адресом `http://` вместо `https://` — значит, перед ядром не передаются заголовки
  `X-Forwarded-*` (`FORWARD_HEADERS_STRATEGY`).
