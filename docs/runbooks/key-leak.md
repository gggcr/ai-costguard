# Утечка ключа или пароля

Решение: [ADR 0028](../adr/0028-secret-rotation.md). Как менять каждый секрет — [secrets.md](secrets.md#ротация).

## Сразу (первый час)
1. **Отозвать**, не дожидаясь замены, если отзыв не останавливает сервис надолго:
   | Утёк | Отозвать |
   |---|---|
   | Ключ провайдера ИИ | В кабинете провайдера; шлюз до замены отвечает агентам ошибкой провайдера |
   | Виртуальный ключ агента | `DELETE /api/v1/agents/{id}/keys/{keyId}` или «Приостановить агента» — шлюз отказывает сразу |
   | Ключ подписи квитанций | Заменить ключ (ниже); старый публичный оставить в `JOURNAL_PREVIOUS_PUBLIC_KEYS` |
   | Ключ нотариуса NEAR | `near account delete-key <аккаунт> <публичный ключ>` после добавления нового |
   | Пароль базы, Kafka, ClickHouse, Redis | `secret_generation` + `terraform apply`, затем секрет |
   | `costguard_backup` | То же: он читает все компании |
   | Закрытый ключ age | Новый ключ, `backups.ageRecipient`; старые копии считать раскрытыми |
   | Токен бота, пароль SMTP, секреты Keycloak | В @BotFather `/revoke`, у почтового сервиса, в консоли Keycloak |
2. **Заменить** по [secrets.md](secrets.md#ротация); Reloader перезапустит сервисы, когда обновится
   `costguard-secrets`.
3. **Записать** время утечки, время отзыва и кто делал — понадобится для уведомления.

## Оценить ущерб (первые сутки)
- Ключ провайдера: траты в кабинете провайдера против `agent_operations` в ClickHouse за период — всё, что провайдер
  списал без операции шлюза, сделано не нами.
- Виртуальный ключ: операции агента за период (`GET /api/v1/agents/{id}` и ClickHouse), квитанции.
- Ключ подписи: проверка цепочки любой компании (`GET /api/v1/journal/verification`) — подделанная квитанция без
  записи в цепочке и якоря в NEAR не пройдёт; якоря в NEAR неизменны.
- Пароли баз и `costguard_backup`: журнал подключений Managed PostgreSQL (консоль Yandex Cloud → Логи) за период,
  незнакомые адреса.
- Административный доступ: журнал действий `GET /api/v1/activity` (ADR 0022) — изменения ролей, бюджетов, удаления.

## Уведомить
Если могли быть раскрыты персональные данные (пароли баз, `costguard_backup`, ключ age вместе с доступом к бакету):
- Роскомнадзор — первичное уведомление в течение 24 часов, итоговое в течение 72 часов (152-ФЗ, ст. 21 ч. 3.1);
- клиенты-операторы — по договору поручения, сразу;
- для клиентов из ЕС — надзорный орган в течение 72 часов (GDPR, ст. 33).
Текст и решение — за юристом ([for-lawyer.md](../privacy/for-lawyer.md)).
