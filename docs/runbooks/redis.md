# Redis шлюза: недоступен, потерял данные, переполнен

В Redis живут счётчики бюджетов шлюза, открытые резервы, одноразовые разрешения на повтор и сохранённые ответы
(ADR 0004, 0020, 0039, 0040). Источник истины по деньгам — журнал проводок в PostgreSQL; Redis — быстрая копия
для решения за миллисекунды. Кластер управляемый: `yandex_mdb_redis_cluster.main` в `deploy/terraform/yandex`.

## Что где лежит
Все ключи компании в одном хеш-слоте `{tenant}`, поэтому Lua-скрипты атомарны и в Redis Cluster.

| Ключ | Что | Сколько живёт |
|---|---|---|
| `cg:{tenant}:b:<budget>` | лимит, версия лимита, `spent`, `reserved` бюджета | всегда |
| `cg:{tenant}:b:<budget>:log` | журнал списаний для восстановления по снимку (ADR 0040) | `costguard.gateway.settlement-log`, сутки |
| `cg:{tenant}:r:<operation>`, `cg:{tenant}:open` | открытый резерв операции и список открытых | до расчёта; брошенные убирает `ReservationSweeper` |
| `cg:{tenant}:s:<operation>` | операция уже рассчитана (повтор settle ничего не меняет) | сутки |
| `cg:{tenant}:a:<operation>` | одноразовое разрешение на повтор после одобрения | `costguard.gateway.approval-ttl`, час |
| `cg:{tenant}:c:<operation>` | первый ответ операции для повтора (ADR 0039) | `costguard.gateway.answer-ttl`, 24 часа |
| `cg:tenants` | компании, по которым ходит уборщик | всегда |

## Redis недоступен
Признаки: `GatewayErrors`, 5xx у шлюза, `RedisConnectionFailure` в логе. Шлюз закрывается (fail closed): без
счётчиков он не может проверить бюджет, поэтому отказывает, а не пропускает.

1. Консоль Yandex Cloud → Managed Redis → кластер `costguard-<env>`: состояние хостов, переключение мастера.
2. `kubectl -n costguard get endpoints`, `kubectl -n costguard exec deploy/costguard-gateway -- getent hosts $REDIS_HOST`.
3. Пароль: секрет `costguard`, ключ `REDIS_PASSWORD` из `terraform output -json secrets` ([secrets.md](secrets.md)). Ошибка `NOAUTH` в логе — пароля нет в секрете или он сменился.
4. Когда Redis вернулся, шлюз восстанавливается сам, перезапуск не нужен.

## Redis потерял данные (рестарт без персистентности, новый кластер)
Ничего делать не нужно, но проверить:
- **Лимиты** приходят снова из компактного `budgets.limits.v1`: шлюз читает его с начала.
- **`spent`** выставит следующий снимок журнала проводок, не позже `costguard.ledger.counter-snapshot-interval`
  (5 минут, ADR 0040). До него агенты тратят от нуля, поэтому при потере данных в рабочее время можно временно
  остановить крупных агентов на странице «Агенты».
- **Открытые резервы** теряются: их settle ответит «резерв неизвестен», операция всё равно придёт в журнал и попадёт
  в следующий снимок.
- **Разрешения на повтор** теряются: одобренную операцию надо одобрить снова.
- **Сохранённые ответы** теряются: повтор получит `409 duplicate_operation`, как до ADR 0039.

Проверка: через 10 минут `BudgetReconciliationMismatch` не горит ([budgets.md](budgets.md)), а остаток бюджета на
странице «Бюджеты» совпадает с журналом.

## Память кончается
Признаки: `used_memory` у потолка в консоли, ошибки `OOM command not allowed` в логе шлюза.
1. Самые большие ключи — сохранённые ответы `:c:`: уменьшить `costguard.gateway.answer-max-bytes` или `answer-ttl`.
2. Иначе — увеличить `redis_preset` в Terraform ([terraform.md](terraform.md)).

## Нельзя
- `FLUSHALL` и удаление ключей `:b:` руками: счётчики восстановятся только через снимок, а до него бюджеты пусты.
- Политика вытеснения, отличная от `NOEVICTION` (задана в Terraform, `maxmemory_policy`): Redis молча выкинет
  счётчик бюджета.
