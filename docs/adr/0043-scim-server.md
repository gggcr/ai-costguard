# 0043. SCIM-сервер для identity-провайдеров

Статус: принято, 2026-11-10.

## Контекст

На доске SCIM — уровень 1 интеграций. В ADR 0042 CostGuard научился читать пользователей у сервисов со SCIM. Но
главный источник сотрудников — сам identity-провайдер компании (Okta, Entra ID, Keycloak, OneLogin, JumpCloud): он
создаёт, меняет и отключает учётные записи и умеет передавать их любому приложению по SCIM 2.0 (RFC 7643, 7644).
Для этого приложение должно быть SCIM-сервером.

Пункт делается в два шага. Первый — здесь: токены, служебные ресурсы и чтение пользователей. Второй — создание,
изменение и отключение.

## Решение

**Токены.** Провайдер ходит в `/scim/v2` с bearer-токеном компании. Его выпускает владелец или ИТ-администратор:
`POST /api/v1/scim/tokens`. Токен показывается один раз, в базе хранится только его SHA-256. Отзыв действует сразу.
По таблице `scim_token` компания находится раньше, чем запрос к ней привязан, поэтому RLS у этой таблицы нет. В ней
лежат только хэши, id и даты, как в `audit_tenant`.

**Своя цепочка безопасности.** Для `/scim/v2/**` работает отдельная цепочка Spring Security. Она стоит раньше цепочки
API и пропускает запрос только с действующим токеном. Ответ 401 приходит в формате ошибки SCIM. JWT Keycloak здесь не
нужен и не принимается.

**Ресурс User.** id пользователя — это id сотрудника. userName — то, что прислал провайдер, а у сотрудника,
заведённого руками, — его почта. Поэтому провайдер, который ищет пользователя по userName, находит людей, которые
были до него, и не создаёт двойников. Как сотрудник известен провайдеру (externalId, userName, отключён ли он),
хранится в `scim_user`. Отдаются:
- name;
- displayName;
- emails;
- title — должность;
- active;
- department — отдел, из расширения EnterpriseUser.

Фильтры — `attribute eq "value"` по userName (без учёта регистра, как в RFC), externalId, emails.value и id: так
провайдеры ищут одного пользователя. Пагинация — по startIndex и count, не больше 200 на страницу. Группы не
поддерживаются: в CostGuard они ничего не значат. ServiceProviderConfig, ResourceTypes и Schemas описывают ровно
это. SCIM не входит в OpenAPI ядра: протокол задаёт RFC.

## Последствия

- Удалённые сотрудники (ADR 0021) провайдеру не показываются.
