# 0058. Вход сотрудников через Microsoft 365 и обязательный код из приложения

Статус: принято, 2026-11-11.

## Контекст

У компаний уже есть Microsoft 365: сотрудники не хотят ещё один пароль. Решено: вход рабочей учётной записью
Microsoft (Entra ID) через Keycloak — основной; вход по паролю остаётся запасным. Учётная запись CostGuard у
человека уже есть (его пригласили, ADR 0036), Microsoft — только способ входа. Для всех, кто входит в браузере,
обязателен одноразовый код из приложения (Google Authenticator и любое TOTP): настраивается при первом входе.

## Решение

- Владелец подключает Entra ID компании (`PUT /api/v1/company/login`): ID каталога, ID приложения, секрет клиента,
  домены почты. Ядро создаёт в Keycloak OIDC-провайдера `ms-{tenant_id}` (issuer
  `https://login.microsoftonline.com/{каталог}/v2.0`, PKCE, скрыт на странице входа) через admin API сервисным
  аккаунтом регистрации (`manage-identity-providers`, `view-identity-providers`). Секрет хранится только в Keycloak;
  при изменении без секрета Keycloak оставляет прежний. В ядре — `company_login` (с RLS) и `login_domain`
  (домен → провайдер, без RLS: читается до входа). `GET/DELETE` тем же адресом; `it_admin` видит настройки.
- Страница входа спрашивает рабочую почту. Публичный `GET /api/v1/login/hint?email=` по домену находит провайдера,
  фронтенд отправляет в Keycloak с `kc_idp_hint` и `login_hint`. Нет провайдера — обычная форма с паролем.
- Домен принадлежит одной компании (`domain_taken`) и только такой, на котором есть почта её пользователей
  (`domain_not_ours`): нельзя занять gmail.com или чужой домен и уводить чужих людей на свой Microsoft.
- Realm: поток браузера `costguard browser` — cookie, переход к провайдеру по подсказке или форма «пароль + код»
  (`auth-otp-form`, обязательный, с настройкой при первом входе). После Microsoft — `costguard post broker` (тот же
  код). Первый вход через Microsoft — `costguard first broker login`: только существующая учётная запись
  (`idp-detect-existing-broker-user`), связь — после подтверждения письмом на её почту или её паролем.
  `trustEmail` выключен: каталог одной компании может записать человеку любой адрес, и без подтверждения он забрал
  бы учётную запись другой компании. Новые учётные записи через Microsoft не создаются.
- Политика кода: TOTP, SHA1, 6 цифр, 30 секунд — то, что понимают Google и Microsoft Authenticator.
- Прямой вход по паролю (direct grant) не меняется: сервисные проверки и демо-сид по-прежнему получают токены.

## Последствия

- После обновления realm все, кто входит в браузере, при следующем входе настраивают приложение-аутентификатор.
  Потерял телефон — администратор Keycloak удаляет у пользователя OTP, и тот настраивает заново
  ([runbook](../runbooks/microsoft-login.md)).
- Удаление компании удаляет её строки; провайдер в Keycloak удаляется отключением входа, а если Keycloak был
  недоступен — отчёт удаления просит сделать это вручную.
- Человек без учётной записи CostGuard через Microsoft не войдёт: сначала приглашение.
