# 0008. Склейка поставщиков и людей по ключам

## Решение
Импорт файлов и коннекторы пишут сущности в `ingest.normalized.v1` с ключом. Поставщик склеивается по ИНН, иначе
по очищенному названию (без формы собственности, кавычек и регистра). Человек — по e-mail, иначе по ФИО. Правила
очистки одинаковы в Python (`costguard_common.normalized`) и Java (`shared/names/Names`).

Ядро хранит каждую сущность в `ingest_entity`. Поставщиков создаёт само. Сотрудников только находит: для
сотрудника нужен отдел, а его знает только человек. Лицензию привязывает, если известны поставщик, подписка и
человек и есть свободное место: платных мест ядро не выдумывает.

## Последствия
- Один поставщик из 1С, МойСклад и загруженного счёта — одна запись.
- Несклеенные сущности ждут человека в `ingest_entity` с пустым `linked_id`.
