# 0007. ClickHouse читает Kafka сам

## Решение
Таблицы с движком Kafka и форматом AvroConfluent читают `cost.records.v1` и `agent.operations.v1`,
материализованные представления пишут в ReplacingMergeTree. Отдельного сервиса-загрузчика нет. Нечитаемые
сообщения попадают в `kafka_errors` и не останавливают чтение. Миграции лежат в `schemas/clickhouse/migrations`,
применяет их `apply.py`; в кластере это Job чарта перед каждым релизом.

## Последствия
- Повторная доставка не задваивает расходы: запись с тем же id заменяется, отчёты читают через `FINAL`.
- Отчёты и прогнозы берут все расходы из `spend_by_month`; ядро знает только расходы агентов.
