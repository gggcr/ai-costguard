# 0015. Банковский коннектор (Т-Банк) и платежи через посредников

## Контекст
Выписки загружают руками (ADR 0012 и задача про MT940/CAMT.053/OFX); нужен ещё ежедневный забор из банка с
открытым API для бизнеса: счета, платежи, операции по корпоративным картам (включая «Мир») и платежи СБП. Часть
зарубежных сервисов оплачивается через посредника: в банке получатель — агент, а деньги — за сервис из
назначения платежа, иногда с комиссией агента.

## Решение
- Интерфейс `costguard_connectors.banks.Bank` (`accounts()`, `operations(account, start, end)`) и
  `BankConnector`, который превращает операции в общий контракт коннекторов. Расход — только списание:
  переводы, карты, СБП, комиссии банка. Поступления и переводы между своими счетами не расходы.
- Первая реализация — Т-Банк (T-Business API, `tbank.TBank`). Причины: токен выпускает сама компания в
  интернет-банке, без сертификатов, VPN и договора с разработчиком; в выписке по счёту есть операции по картам с
  маской карты и мерчантом, есть категория СБП. У Сбера и Альфы для API нужно подключение партнёра с
  сертификатом. Точка тоже подошла бы; её стоит сделать второй реализацией `Bank`. Платёжная система карты (МИР, Visa, Mastercard,
  UnionPay) определяется по первым цифрам номера и пишется в PAYMENT (`card_network`).
- Формы ответов взяты из публичной документации банка и проверены на записанных ответах (`httpx.MockTransport`),
  не на живом счёте. Названия категорий нужно сверить с песочницей банка до первого клиента.
- Курсор — день последней операции по каждому счёту; следующий забор начинается с этого дня снова, чтобы не
  потерять операцию, проведённую задним числом. Стабильные ключи делают повтор безвредным. Первый забор — за 90 дней.
- Посредники (`costguard_common.payments`), одинаково для выписок в ingest и для банковского коннектора, до
  Kafka (Python). Посредник — получатель из списка (ИНН или название, `INGEST_PAYMENT_INTERMEDIARIES` и
  `[payments]` в конфигурации коннекторов) или любой получатель, в назначении которого есть агентский договор.
  Сервис ищется по названию в назначении или в дескрипторе карты: встроенный словарь известных сервисов плюс
  названия компании. PAYMENT и cost record пишутся на сервис, без ИНН агента, поэтому ядро склеивает их с
  поставщиком-сервисом по названию, как любой платёж (ADR 0008). Ядро не менялось.
- Комиссия посредника выделяется отдельным PAYMENT и cost record на агента, только если её сумма есть в
  назначении («в т.ч. вознаграждение агента 350 руб.»). Иначе вся сумма идёт на сервис с пометкой
  `commission_unknown`: придуманная комиссия была бы неверным числом в отчётах. Не видно сервиса — платёж
  остаётся платежом агенту с пометкой `service_unknown`.

## Последствия
- Комиссия, которую агент удерживает без указания в назначении, попадает в стоимость сервиса.
- Словарь сервисов нужно пополнять; компания может добавить свои названия, не дожидаясь релиза.
- Для другого банка достаточно реализовать `Bank`: разбор операций в платежи, посредники и курсор общие.
