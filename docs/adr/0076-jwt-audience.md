# 0076. Ядро принимает только токены, выданные для него

Статус: предложено, 2026-11-23. Дополняет ADR 0001 и 0021.

## Контекст

Ядро проверяло подпись, издателя и срок токена, но не его адресата (`aud`). Любой токен realm `costguard`
открывал API: и токен сервисного аккаунта `costguard-privacy` или `costguard-registration`, и токен любого
клиента, которого администратор добавит в realm для другого приложения. Роли в токене решают, что можно, но
клиент, сделанный не для CostGuard, не должен попадать в API вовсе. Покупатель на проверке безопасности
спросит именно это.

## Решение

- Клиенты, которые ходят в ядро (`costguard-frontend`, `costguard-e2e`, сервисные аккаунты коннекторов,
  прогнозов и выгрузок), кладут в access token адресата `costguard-api` маппером `oidc-audience-mapper`.
  Маппер есть в `infra/keycloak/costguard-realm.json` и в realm чарта.
- Ядро требует этого адресата: `spring.security.oauth2.resourceserver.jwt.audiences` из `JWT_AUDIENCE`
  (по умолчанию `costguard-api`). Пустое значение не выключает проверку, а не даёт ядру стартовать.
- Подпись — только RS256 (`jws-algorithms`), как подписывает Keycloak: неподписанный токен и HS256 с открытым
  ключом в роли секрета отклоняются. Издатель, срок и `nbf` проверяются, как и раньше.
- Тест `JwtValidationIntegrationTest` гоняет настоящие токены через настоящий декодер (ключи по HTTP, как у
  Keycloak): правильный адресат, чужой, без адресата, истёкший, ещё не действующий, чужой издатель, чужой ключ,
  без подписи, подмена алгоритма, испорченный токен, роли не из `realm_access`.

## Последствия

- Realm импортируется только при первом запуске Keycloak (docs/runbooks/keycloak.md). В работающей установке
  маппер нужно добавить **до** обновления ядра, иначе входы перестанут работать: клиент → Client scopes →
  Dedicated scope → Add mapper → Audience, Included Custom Audience `costguard-api`, Add to access token.
  То же для каждого сервисного клиента компаний.
- Сервисные аккаунты `costguard-privacy` и `costguard-registration` в ядро больше не пускаются; им это и не нужно.
- Шлюз JWT не принимает (у агентов ключи API), его это не касается.
