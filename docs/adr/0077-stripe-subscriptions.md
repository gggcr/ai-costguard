# 0077. Подписки через Stripe

Статус: предложено, 2026-11-23. Дополняет ADR 0037 и 0038.

## Контекст

Оплата тарифа (ADR 0038) — разовый платёж за месяц через интерфейс провайдера; реального провайдера не было,
только заглушка. Западным компаниям нужна подписка с автопродлением, оплата картой в долларах и евро, счета и
отмена без письма в поддержку. Владелец продукта выбрал Stripe.

## Решение

- **`StripePaymentProvider`** (`PAYMENT_PROVIDER=stripe`) реализует прежний интерфейс через REST API Stripe без SDK:
  Checkout в режиме `subscription`, портал клиента (`billing_portal/sessions`), вебхуки. Ключ — только из окружения
  (`STRIPE_SECRET_KEY`), в браузер он не попадает: браузер получает лишь адрес страницы Stripe. Карта вводится на
  странице Stripe, ядро видит только id, статусы, периоды и суммы. Без ключа, секрета вебхука или цен ядро с
  `PAYMENT_PROVIDER=stripe` не стартует.
- **Цены по валютам.** У тарифа в каталоге есть `prices` (валюта → цена в месяц): start — 149 USD / 139 EUR,
  business — 699 USD / 649 EUR; рублёвая цена остаётся основной. Каждой паре «тариф-валюта» соответствует цена
  Stripe (`STRIPE_PRICE_START_USD` и т. д.); сумма в каталоге должна совпадать с суммой цены в Stripe.
  `POST /api/v1/billing/checkout` принимает `currency`; валюта без цены — `400 plan_currency_unknown`.
- **Одна подписка на компанию** (`plan_subscription`, RLS). Пока она живёт (active, past_due и т. п.), новый
  checkout отвечает `409 subscription_exists`: смена тарифа, карта, отмена и счета — в портале Stripe
  (`POST /api/v1/billing/portal`, только владелец). После отмены новый checkout идёт на того же клиента Stripe.
- **Вебхуки** приходят на прежний `POST /api/v1/billing/notifications/stripe`. Подпись `Stripe-Signature`
  (HMAC-SHA256 секретом конечной точки) проверяется с допуском 5 минут: неподписанное, чужое и старое уведомление —
  `400`, ничего не меняется. Используются события:
  - `checkout.session.completed` / `async_payment_succeeded` — платёж ядра проходит (как раньше), подписка
    записывается; `checkout.session.expired` / `async_payment_failed` — платёж отменяется;
  - `invoice.paid` — оплачен период: доступ до конца периода Stripe (берётся более поздняя дата, повтор и
    опоздавшее событие срок не сокращают), продление попадает в историю платежей;
  - `invoice.payment_failed` — статус `past_due`; компания работает ещё `PAYMENT_GRACE` (7 дней) после конца
    оплаченного периода, пока Stripe повторяет списание; льгота считается от оплаченного, а не от «сейчас», так что
    повторные отказы её не продлевают;
  - `customer.subscription.updated` — смена тарифа в портале (цена → тариф), отмена в конце периода;
    `customer.subscription.deleted` — подписка закончилась, доступ идёт до конца оплаченного;
  - остальные события подтверждаются `200` и ничего не меняют.
- **Повторы и порядок.** Id события хранится в `plan_billing_event` в той же транзакции, что и изменение: повтор
  ничего не меняет. Событие о подписке, которой ядро ещё не знает (пришло раньше `checkout.session.completed`),
  получает `409`, и Stripe доставит его снова. Статус из события старше сохранённого не применяется.
- **Статус оплаты решает только ядро** по проверенному уведомлению: страница возврата (`?checkout=success`) лишь
  перечитывает тариф. «Только чтение» по-прежнему наступает, когда кончается `access_until` (ADR 0037).
- **История платежей** — `GET /api/v1/billing/payments` (владелец и финансы); счета и квитанции Stripe — в портале.
- **Налоги.** `STRIPE_AUTOMATIC_TAX=true` включает Stripe Tax в Checkout (нужна регистрация в Stripe Tax).
- **Интерфейс.** Страница «Тариф и оплата» (`/settings/plan`): тариф и срок, цены в валюте компании, оформление
  подписки, портал, история платежей.

## Последствия

- Миграция V53: `plan_subscription`, `plan_subscription_ref`, `plan_billing_event`; удаление компании (ADR 0021)
  удаляет и их.
- Новые переменные: `STRIPE_SECRET_KEY`, `STRIPE_WEBHOOK_SECRET`, `STRIPE_PRICE_{START,BUSINESS}_{USD,EUR}`,
  `STRIPE_AUTOMATIC_TAX`, `PAYMENT_GRACE`. Настройка аккаунта — docs/STRIPE_SETUP.md, работа с оплатами —
  docs/BILLING_OPERATIONS.md.
- Тесты `StripeBillingIntegrationTest` идут против подставного API Stripe на локальном порту с настоящими
  подписями вебхуков. С настоящим аккаунтом Stripe (даже тестовым) интеграция не проверялась: ключей нет.
- Stripe не работает с компаниями из России: нужен аккаунт юрлица в поддерживаемой стране.
