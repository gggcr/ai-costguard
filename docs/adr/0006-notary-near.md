# 0006. Нотариус: дерево Меркла и NEAR, без тенанта в сети

## Решение
Квитанции разрешённых операций образуют цепочку хешей и подписаны Ed25519 (модуль `journal`). Нотариус
(`apps/python/notary`) собирает их в пакеты по компании, строит дерево Меркла и записывает корень в контракт
`contracts/notary`. Дерево одинаково в Java, Python и Rust: эталонный корень закреплён в тестах всех трёх.
Контракт хранит только корень, число квитанций и период — ни компании, ни сумм.

Повтор того же пакета с тем же корнем контракт принимает без ошибки и без изменений, поэтому нотариус может
повторить вызов после сбоя. Тот же пакет с другим корнем отклоняется.

## Последствия
- Любой может проверить квитанцию методом `verify` контракта, не доверяя CostGuard.
- Ядро отмечает квитанции заякоренными, только если корень сошёлся с его собственным расчётом.
