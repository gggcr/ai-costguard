# 0001. Ядро — модульный монолит на Spring Modulith

## Контекст
У ядра десяток областей: org, software, assets, imports, findings, ledger, journal, approvals и другие. Они
делят одну базу и одну транзакцию на запрос. Микросервисы на этом этапе дали бы распределённые транзакции без
выгоды: нагрузка на ядро небольшая, горячий путь — в gateway.

## Решение
Одно приложение, модули — пакеты верхнего уровня. Наружу модуль отдаёт только типы корневого пакета, всё в
`internal` закрыто. `ModuleBoundariesTest` проверяет границы при каждой сборке. Модули общаются вызовами
публичных интерфейсов и событиями Spring; в Kafka события уходят через outbox Spring Modulith.

## Последствия
- Модуль можно вынести в сервис, когда понадобится: границы уже проверены.
- Таблицы принадлежат модулям (комментарий `Owned by` в миграции), чужие таблицы модуль не читает.
