# 0046. FOCUS-выгрузки из бакета компании по расписанию

Статус: принято, 2026-11-10.

## Контекст

В пункте 9 FOCUS-файлы научились разбираться без человека: колонки названы по спецификации и сопоставляются точно
(ADR 0042). Но файл всё ещё надо было загрузить руками. Облака (AWS Data Exports, Azure Cost Management, Google Cloud,
Yandex Cloud) сами кладут FOCUS-выгрузки в бакет компании, каждый день или чаще. Ходить за ними должен CostGuard.

## Решение

**Задача.** `costguard-focus-pull` (пакет ingest, где boto3 уже есть) раз в час читает бакет компании через любой
S3-совместимый API: AWS S3, Yandex Object Storage, MinIO. DAG `costguard_focus_bucket` запускает её для каждой
компании, у которой в настройках есть раздел `[focus_bucket]`.

**Через API импорта.** Новые файлы загружаются в ядро через `POST /api/v1/imports`, как их загрузил бы человек.
Поэтому:
- у файла тот же путь: хранилище, разбор, «Импорт»;
- проверка sha256 в ядре не даёт загрузить файл дважды.

Какие объекты уже прочитаны (ключ и ETag), записано в файле состояния. Каждый запуск скачивает только новое и
изменённое.

**Какие файлы читаются.**
- `.csv`, `.csv.gz` (распаковывается перед загрузкой), `.xlsx`, `.parquet`.
- Parquet читается через pyarrow, и в импорте у него свой тип `parquet` (V33). Сначала это был пропуск с причиной:
  в окружении не было uv, чтобы пересобрать lock-файл. Когда uv появился, Parquet добавили.
- Объекты старше окна (по умолчанию 7 дней) не читаются. Иначе первый запуск загрузил бы годы выгрузок.

**Ошибки.** Если загрузка в ядро не прошла, файл берётся снова в следующий запуск. Битый архив не берётся, пока у
него не сменится ETag. Запуск с ошибками в Airflow красный; то, что успело загрузиться, остаётся загруженным.

**Автоподтверждение.** С `accept` (по умолчанию включено) задача дожидается разбора файла. Разметку она подтверждает
сама, только если нигде не нужен человек:
- это FOCUS-файл (есть `BilledCost` и `ChargePeriodStart`);
- нет строк с ошибками;
- нет значений, в которых конвейер не уверен;
- есть колонка суммы.

Остальное ждёт в «Импорте», как загрузка руками.

**Роль.** Сервисный аккаунт задачи получает новую роль `importer`. Она даёт загрузить файл и подтвердить разметку,
но не разрешает исправлять значения: это по-прежнему делают люди. Ключ к бакету нужен только на чтение.

## Последствия

- Проверено на открытых обезличенных данных FOCUS 1.0 от FinOps Foundation (FOCUS-Sample-Data, CC BY 4.0;
  AWS, Microsoft, Oracle, Google). 100 000 строк, 73 МБ CSV: разметка точная, ошибок и сомнительных значений нет,
  сумма `BilledCost` совпадает с посчитанной напрямую до 11-го знака (1426.92236906705 USD). Те же строки в Parquet
  (6 МБ) дают ту же сумму.
- Записи расходов хранят сумму с 6 знаками. Почасовые траты облака меньше микродоллара округляются: на 1000 строк
  образца сумма записей 20.520216 против 20.52022672899 в файле.
- Одна загрузка в ядро — до 50 МБ: столько пропускает nginx. Файл больше этого, уже распакованный, пропускается с
  причиной. Крупным облакам надо делить выгрузку на части; AWS и Azure так делают сами.
- Состояние лежит на диске воркера Airflow (`$COSTGUARD_STATE_DIR`). Если оно потеряется, файлы из окна прочитаются
  снова, и дубли не появятся только благодаря sha256 в ядре.
- С реальным бакетом облака не проверялось. S3-клиент проверен на заглушке botocore, ядро в тестах подменено.
