# 0050. Трейсы Python-сервисов и сквозной трейс через Kafka

Статус: принято, 2026-11-11.

## Контекст

С ADR 0048 трейсы отправляли только ядро и шлюз. Python-сервисы (ingest, anomaly, notary, коннекторы, прогноз и
отчёты) трейсов не писали. К тому же ядро и шлюз публиковали в Kafka без заголовка `traceparent`, поэтому трейс
обрывался на шине. Например, путь загруженного файла от запроса в ядро до записей затрат нельзя было увидеть одним
трейсом.

## Решение

- `costguard_common.tracing` — общий модуль на OpenTelemetry SDK. Он включается, когда `COSTGUARD_TRACING=true` и
  задан `OTEL_EXPORTER_OTLP_TRACES_ENDPOINT`; Helm ставит обе переменные при `tracing.enabled`. Выключенный модуль
  оставляет OpenTelemetry API пустышкой, и вызовы ничего не стоят.
  - `consumed(msg)` — спан CONSUMER на обработку одного сообщения. Он продолжает трейс из заголовка `traceparent`.
  - `headers()` — заголовки для исходящих сообщений, чтобы трейс шёл дальше.
  - `job(service, name)` — один спан на прогон задачи: агент коннекторов, `costguard-focus-pull`,
    `costguard-forecast`, `costguard-report`.
  - Вызовы через httpx (ядро, NEAR, шлюз, MLflow) становятся дочерними спанами и сами несут `traceparent`.
- ingest, anomaly и notary оборачивают обработку каждого сообщения в `consumed` и публикуют с `headers()`.
- В ядре и шлюзе у `KafkaTemplate` включено observation: у каждой отправки есть спан PRODUCER и заголовок
  `traceparent`.
- Решение о сэмплировании принимает тот, кто начал трейс. В кластере это ядро и шлюз (`TRACE_SAMPLING`, 0.1).
  Python-сервис его соблюдает: в не записанном трейсе он тоже ничего не пишет. Локально (`TRACING=true make demo
  observability`) записываются все трейсы.
- В спаны попадают топик, партиция и смещение, содержимое сообщений — никогда (ADR 0023). Collector дополнительно
  вырезает атрибуты с персональными данными (ADR 0048).

## Последствия

- Проверено на демо-стенде: загрузка Excel даёт в Tempo трейс, который начинается в ядре на отправке
  `ingest.files.v1` и продолжается спанами `costguard-ingest`.
- Отправка из outbox ядра идёт после фиксации транзакции, в отдельном потоке. Поэтому трейс начинается с отправки
  события, а не с HTTP-запроса пользователя; связать их можно по времени и ID загрузки.
- В `costguard-common` появились зависимости OpenTelemetry: api, sdk, otlp-proto-http и instrumentation-httpx.
