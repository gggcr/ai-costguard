# 0027. Безопасность в CI: Trivy, npm audit и gitleaks; сборка падает на критических уязвимостях

## Контекст
Перед запуском нужны проверка зависимостей Java, Python, JS и Rust, сканирование образов и поиск секретов в коде.
Сборка должна падать на критических уязвимостях. Lock-файлы есть у Python (`uv.lock`), фронтенда
(`package-lock.json`) и контракта NEAR (`Cargo.lock`); у Gradle lock-файла нет, версии задают BOM.

## Решение
- **Один сканер уязвимостей — Trivy** (`aquasec/trivy`, версия закреплена в `.github/workflows/security.yml`):
  - `trivy fs` по репозиторию читает `uv.lock`, `package-lock.json` и `Cargo.lock`;
  - Java — `trivy rootfs` по собранным `core.jar` и `gateway.jar`: это fat jar со всеми зависимостями, ровно то, что
    запускается, без отдельного плагина Gradle;
  - образы `core`, `gateway`, `python`, `backup`, `mlflow` собираются в CI и проверяются `trivy image` вместе с ОС.
  Дополнительно `npm audit --omit=dev --audit-level=critical` для фронтенда: он видит advisories npm раньше.
- **Порог.** Падает на `CRITICAL`, для которого есть исправление (`--ignore-unfixed`): обновить зависимость — работа
  разработчика, а уязвимость без исправления в базовом образе сборкой не лечится. Всё остальное, от `HIGH` и ниже и
  без исправлений, уходит SARIF во вкладку Security и видно там.
- **Исключения** — `.trivyignore`: CVE, почему она нас не достаёт, кто решил и до какой даты. Просроченная строка —
  ошибка, её удаляют или продлевают с причиной.
- **Секреты — gitleaks** с правилами по умолчанию и тремя своими: виртуальный ключ агента `cg_live_…`, ключ NEAR
  `ed25519:…`, закрытый ключ подписи квитанций (PKCS#8 Ed25519). В pull request проверяются его коммиты, на `main` и
  раз в неделю — вся история. Исключения перечислены в `.gitleaks.toml` по путям: подделки для тестов маскирования,
  локальный стек и его импорт Keycloak (только для ноутбука, README), тесты.
- **Когда.** На каждый pull request и push в `main`, и по понедельникам: новая CVE в зависимости, которую никто не
  трогал, тоже должна всплыть.

## Последствия
- Сборка образов в `security` дублирует будущую сборку для публикации; когда появится workflow публикации образов,
  сканирование переедет в него, чтобы проверялся ровно опубликованный образ.
- Trivy не знает транзитивных версий Gradle без jar: уязвимость в зависимости, которая не попала в jar, не найдётся,
  но и не запустится.
- gitleaks по путям `tests/` не смотрит: настоящий ключ, положенный в тест, он пропустит. Тесты генерируют ключи сами,
  это правило ревью.
