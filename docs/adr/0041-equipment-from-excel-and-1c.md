# 0041. Техника из Excel и 1С, отдельные находки по возврату

Статус: принято, 2026-11-10.

## Контекст

На кадре 15 доски техника приходит из 1С, Jamf, Intune и Excel, а находки по ней такие: «уволенный не сдал
технику», «срок возврата прошёл», «техника лежит на складе», «два ноутбука у сотрудника». Jamf и Intune были
подключены. Из 1С и Excel технику можно было завести только руками по одной записи. «Не сдал» и «срок прошёл» были
одним правилом `asset.not-returned`.

## Решение

**Excel.** У разбора появились поля `inventory_number`, `serial_number`, `asset_model` и `asset_type` (с синонимами
вроде «Инв. номер», «Серийный номер», «Модель»), и ядро принимает их в сопоставлении. Таблица с колонкой
инвентарного или серийного номера — это список техники. Каждая строка становится устройством (`ASSET`), а сотрудник
строки — его держателем. Сумма строки — это стоимость устройства, а не трата, поэтому записи затрат, подписки и счёт
из такой таблицы не создаются. Строка без обоих номеров пропускается с причиной. Колонка суммы для списка техники
не обязательна.

**1С.** Коннектор 1С читает справочник основных средств 1С:Бухгалтерии: инвентарный номер, заводской номер,
наименование как модель и тип, угаданный по наименованию. Держатель — МОЛ из последней записи регистра
местонахождения основных средств. В конфигурации без основных средств (1С:УТ) этих сущностей нет, ответ 404, и
читаются только счета. Ключ устройства тот же, что у Jamf и Intune (серийный номер, иначе инвентарный), поэтому одно
устройство из разных источников остаётся одной записью.

**Тип по названию** определяет `costguard_common.normalized.asset_kind`, одна функция для Excel и 1С.

**Находки.** `asset.not-returned` — уволенный не сдал технику. `asset.overdue` — срок возврата прошёл, а сотрудник
ещё работает. Устройство уволенного не попадает в обе находки сразу. Возврат техники подтверждает или закрывает обе,
как раньше одну (ADR 0020).

**Фронтенд.** Экран сопоставления показывает русские подписи полей, а API ядра ждёт идентификаторы. В режиме API
подписи отправлялись как есть, и ядро отклонило бы сопоставление. Теперь `api/focus.ts` переводит подписи в
идентификаторы и обратно на границе с API.

## Последствия

- Найденные раньше просрочки возврата (`asset.not-returned` без увольнения) при следующем аудите закроются сами, а
  взамен откроются как `asset.overdue`.
- Стоимость техники из 1С не читается: она лежит в регистрах учёта по периодам. Её вводят в CostGuard.
