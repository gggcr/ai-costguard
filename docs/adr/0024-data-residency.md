# 0024. Данные в одном регионе, заданном одной настройкой

## Контекст
152-ФЗ (ст. 18 ч. 5) требует записывать и хранить персональные данные граждан России в базах на её территории.
Проверка `deploy/` показала: все хранилища фактически в `ru-central1`, но регион и зоны были прописаны в разных
местах (`zones` в переменных Terraform, `region = "ru-central1"` в кластере Kubernetes, адрес S3 в values Helm).
Зону из чужого региона можно было указать в одном месте, не заметив в другом. Клиенты S3 не знали регион подписи.

## Решение
- **Terraform** (`deploy/terraform/yandex`): одна переменная `region` (по умолчанию `ru-central1`). Зоны выводятся из
  неё (`zone_suffixes` → `<region>-a`, `-b`, `-d`), переменной `zones` больше нет. Из этих зон берут подсети
  PostgreSQL, Kafka, ClickHouse, Redis и узлы Kubernetes; региональный мастер Kubernetes — `var.region`; провайдер
  получает адрес Object Storage этого региона из `local.storage_endpoints`. Для региона без известного адреса план
  останавливается до создания чего-либо. Метки ресурсов несут `region`. Выходы `region` и `s3_endpoint` переносятся
  в Helm.
- **Helm**: одно значение `region`, то же, что в Terraform. Из него берутся адрес S3 (`regions.<region>.s3Endpoint`,
  если `external.s3Endpoint` не задан) и переменные `S3_REGION`, `DATA_REGION`, `AWS_DEFAULT_REGION` для MLflow.
  Неизвестный регион роняет рендер. Окружения регион не переопределяют.
- **Бэкенд состояния Terraform** не умеет читать переменные: его `region` в `backend.tf.example` должен совпадать, это
  проверяет тест.
- `tools/tests/test_residency.py` проверяет, что в `main.tf` нет зон и регионов текстом, кроме ключа карты адресов,
  что каждая строка `zone`/`region` выводится из `region`, что все хранилища с данными в модуле и что Helm и
  Terraform называют один регион. С установленным `helm` тест рендерит чарт и проверяет переменные сервисов.

## Что за пределами этой настройки
- **Keycloak и Vault** Terraform не создаёт; values указывают на внешний `id.costguard.example`. Их нужно развернуть в
  том же регионе, это шаг runbook, а не настройка.
- **Провайдеры ИИ.** Шлюз передаёт запросы агентов провайдерам; OpenAI и Anthropic за рубежом. Шлюз не хранит
  текст запросов, но передача есть. LLM-извлечение счетов (ADR 0013) идёт через шлюз к провайдеру из
  `INGEST_LLM_PROVIDER` (по умолчанию `openai`): для данных в стране нужен `yandex` или `gigachat`. Вопрос о
  трансграничной передаче — у юриста ([for-lawyer.md](../privacy/for-lawyer.md)).
- **NEAR** — публичная сеть без региона; туда уходят только хэши без компании и людей (ADR 0006, ADR 0009).
- **Логи**: сборщик логов, когда он появится, тоже должен быть в регионе.

## Последствия
- Перенос в другой регион — одна переменная в Terraform, одно значение в Helm и адрес Object Storage в двух картах.
  Существующие кластеры при смене региона пересоздаются; это перенос данных, а не настройка.
- Удалённая переменная `zones` ломает старые tfvars, где она задана; в репозитории таких нет.
