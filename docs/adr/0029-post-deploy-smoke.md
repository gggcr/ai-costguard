# 0029. Проверка после выкладки: smoke-тест staging после синхронизации Argo CD

## Контекст
Staging следует за `goidochka` через Argo CD (`deploy/argocd/staging.yaml`, автосинхронизация). Workflow, который бы
выкладывал, нет: выкладывает Argo CD. Нужен smoke-тест после развёртывания — вход, создание агента, операция через
шлюз с резервом и списанием, загрузка Excel, появление находки — подключённый к workflow deploy.

## Решение
- **Тест** — `tests/smoke/test_staging.py`, обычный pytest на SDK `costguard` и httpx; без `SMOKE_CORE_URL`
  пропускается. Шаги: вход паролем через клиент Keycloak `costguard-smoke`; мандат, сотрудник-владелец, агент, ключ,
  бюджеты до агента; через шлюз — резерв (проверено, что резерв держит деньги: второй запрос сверх остатка получает
  `budget_exceeded`) и списание; в ядре — проводка на бюджете агента и квитанция; загрузка Excel с одной строкой
  дважды, подтверждение предложенных колонок; детектор аномалий находит двойное списание, находка появляется в ядре.
  Каждый шаг ждёт до `SMOKE_TIMEOUT_SECONDS` (5 минут): данные идут через Kafka.
- **Где** — отдельная компания smoke-пользователя в Keycloak staging; имена содержат id запуска, запуски не мешают
  друг другу. После теста ключ отозван, агент приостановлен.
- **Когда** — job `smoke-staging` в `deploy.yml`: после успешной сборки `goidochka` (`workflow_run` от java, python,
  frontend) и вручную. Он ждёт, пока Argo CD покажет приложение `costguard-staging` синхронным и здоровым **на этом
  коммите**, и только потом запускает тест. Не дождался за 20 минут — падает.
- **Настройки** — environment `staging` репозитория: переменные `SMOKE_CORE_URL`, `SMOKE_GATEWAY_URL`,
  `SMOKE_KEYCLOAK_URL` и секреты `SMOKE_USERNAME`, `SMOKE_PASSWORD`, `ARGOCD_SERVER`, `ARGOCD_AUTH_TOKEN` (токен
  проекта Argo CD только на чтение приложения). Без них job падает и называет недостающее: «зелёный» без проверки
  хуже красного.

## Последствия
- Smoke-тест создаёт данные на staging: мандаты, агенты, загрузки и находки компании smoke копятся. Её можно удалить
  целиком (ADR 0021) и завести заново.
- Тест проверяет путь, а не производительность и не все роли; нагрузку проверяет `tests/load`.
- Для prod тот же тест подключается так же, когда появится выкладка prod по тегу (`deploy/argocd/prod.yaml`).
- Excel и находка зависят от пайплайна и детектора аномалий: если тест падает на шаге 5 при здоровом шаге 4, смотреть
  `costguard-anomaly` (docs/runbooks/smoke.md).
