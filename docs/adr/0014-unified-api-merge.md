# 0014. Единый API — Merge, а не Codat или Finch

## Контекст
Клиентам с зарубежными учётными и кадровыми системами (QuickBooks, Xero, NetSuite, BambooHR, Workday, Personio)
отдельный коннектор к каждой не напишешь. Нужен один адаптер, который отдаёт и учёт (поставщики, счета, платежи),
и кадры (сотрудники, увольнения) по общему контракту коннекторов.

## Решение
- Merge (`costguard_connectors.merge`). Из трёх кандидатов только он закрывает обе категории одним API:
  Codat — учёт, банк и коммерция без кадров; Finch — кадры и зарплата без учёта. С ними понадобились бы два
  поставщика и два договора.
- Компания подключает каждую систему в Merge Link отдельно; у учётной и у кадровой системы свой account token.
  Ключ API CostGuard — `MERGE_API_KEY`, токены — `MERGE_ACCOUNTING_TOKEN` и `MERGE_HRIS_TOKEN`; любой из
  токенов может отсутствовать.
- Учёт: поставщики (`contacts?is_supplier=true`) — VENDOR с ИНН/налоговым номером; счета к оплате
  (`invoices?type=ACCOUNTS_PAYABLE`, кроме черновиков и аннулированных) — INVOICE и cost record; платежи — PAYMENT
  без cost record, потому что они оплачивают уже учтённые счета.
- Кадры: сотрудники по рабочему e-mail; `INACTIVE` с датой увольнения — `dismissed`, это может сказать только
  кадровая система (ADR 0008).
- Курсор — время прошлого забора по каждой категории, следующий забор просит `modified_after`. Поставщики
  читаются целиком: счёт, изменённый сегодня, может быть от поставщика, не менявшегося год.

## Последствия
- Российских систем (1С, МойСклад, 1С:ЗУП) у Merge нет: для них остаются свои коннекторы.
- Данные клиента проходят через Merge (США/ЕС). Это нужно согласовывать с клиентом до подключения.
- Проверено на записанных формах ответов Merge (`httpx.MockTransport`), не на живом аккаунте.
