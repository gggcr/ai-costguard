# 0079. Выгрузка персональных данных сотрудника

Статус: предложено, 2026-11-23. Дополняет ADR 0021.

## Контекст

Стирание данных человека и сроки хранения есть (ADR 0021), а выгрузки нет. Для западных клиентов это обязательная
функция: право на доступ и переносимость (GDPR, ст. 15 и 20) и «право знать» (CCPA). Клиент (работодатель) —
контролёр, он отвечает на запросы своих сотрудников; CostGuard как обработчик должен дать ему инструмент.

## Решение

- `GET /api/v1/employees/{id}/personal-data` — только владелец, как и стирание. Ответ — JSON: таблица за таблицей
  (`модуль.таблица` → строки как они хранятся), плюс `erased` и время выгрузки.
- Каждый модуль сам выгружает свои таблицы (`DataHolder.exportEmployee`), по тем же признакам, по которым стирает:
  id сотрудника, его адреса почты. Секреты (хэш ПИН-кода подписи, TOTP, файлы, PDF) не выгружаются: только метаданные.
- Тест требует, чтобы каждый модуль, который стирает данные человека, их и выгружал: новый модуль не забудет.
- Выгрузка записывается в журнал действий (`privacy.employee_exported`, без содержимого).

## Последствия

- Юридические черновики (docs/legal) ссылаются на эту функцию в процедурах GDPR и CCPA.
- Самообслуживания для сотрудника нет: запрос идёт через работодателя.
