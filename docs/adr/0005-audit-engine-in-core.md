# 0005. Движок аудита внутри ядра, а не отдельным сервисом

## Контекст
На доске движок аудита — отдельный сервис. Правилам нужны лицензии, последняя активность, подписки, договоры,
уволенные и техника. Всё это живёт в PostgreSQL ядра, а топиков с этими данными нет. Отдельный сервис пришлось
бы кормить копией половины базы.

## Решение
Интерфейс `findings.AuditRules`: модуль сам проверяет свои данные и возвращает находки. Правила софта лежат в
`software`, правила техники — в `assets`. `AuditEngine` раз в час обходит компании из `audit_tenant` и закрывает
находки, условие которых пропало. Внешние детекторы (аномалии) пишут в `findings.v1`, ядро читает этот топик
в тот же `FindingsIntake`.

## Последствия
- Новое правило — класс в модуле-владельце данных, без новых топиков.
- Правила по длинной истории расходов сюда не идут: им место в детекторе аномалий поверх ClickHouse.
