# 0047. Свой образ у каждого Python-сервиса

Статус: принято, 2026-11-11.

## Контекст

Правило репозитория на доске: один сервис — одна папка, в ней код, тесты, Dockerfile и README, владелец в
`CODEOWNERS`. Java-сервисы так и устроены. Python-сервисы собирались в один образ `apps/python/Dockerfile`, в
котором стояли все пять пакетов, а нужный сервис выбирала команда. Из-за этого в каждом поде лежали чужие
зависимости: Tesseract нужен только приёму файлов, scikit-learn и river — только детектору. Образ был тяжелее, а уязвимость в любой из этих зависимостей попадала во все сервисы. README был
только у `connectors`.

## Решение

- У каждого сервиса свой `apps/python/<сервис>/Dockerfile`: `ingest`, `anomaly`, `notary`, `connectors`,
  `reports`. Контекст сборки — корень репозитория, потому что там workspace uv и общий `uv.lock`. В образ ставится
  только свой пакет и его зависимости: `uv sync --frozen --no-dev --package costguard-<сервис>`.
- Системные пакеты — только там, где нужны: Tesseract в `ingest` (ADR 0012).
- Окружение собирается в `/app`, там же, где оно работает: скрипты запуска (`costguard-ingest` и другие) начинаются
  с абсолютного пути к python окружения. В старом общем образе окружение собиралось в `/src` и копировалось в `/app`,
  и ни одна команда не запускалась (`no such file or directory`). CI проверяет первую строку каждой команды.
- Из `reports` убрана зависимость `lightgbm`: код её не использовал, бустинг ADR 0045 написан на чистом Python.
- `schemas/avro` есть в каждом образе. `schemas/clickhouse` — только в `ingest`: из него Helm запускает задание
  миграций ClickHouse.
- Helm: `ingest`, `anomaly`, `notary` берут образы своих имён; задание миграций — образ `ingest`, CronJob
  коннекторов — образ `connectors`. Образа `python` больше нет.
- CI собирает и проверяет пять образов матрицей (`python.yml`), Trivy сканирует каждый (`security.yml`).
- README у каждого сервиса: что делает, топики, команды, переменные окружения, тесты. Отдельная строка на каждый
  сервис в `CODEOWNERS`.

## Последствия

- Реестр образов должен содержать `ingest`, `anomaly`, `notary`, `connectors` и `reports` вместо `python`. Тег тот
  же, `image.tag`.
- Сборка в CI идёт пять раз, но параллельно; слои с uv и зависимостями у каждого свои.
- Airflow локально по-прежнему ставит `connectors` и `reports` из исходников (`infra/local/docker-compose.yml`).
