# 0057. Теневые траты: легально, анонимно, сводкой от трёх человек

Статус: принято, 2026-11-11.

## Контекст

Седьмая часть кабинета (ADR 0051). Сотрудники платят за рабочие программы своими картами, чтобы быстрее сделать
работу, и молчат: боятся нарушить правила. Нужно, чтобы сотрудник мог легально и анонимно сообщить о такой покупке
через форму или Excel. Система сама относит трату к категории и показывает руководству, какой сервис нужен. Решено:
руководство видит только сводку — сервис, отдел, сумма, без имён — и только от трёх сообщений.

## Решение

- Сообщение — `shadow_spend` модуля `cabinet`: сервис, категория, сумма, валюта, дата оплаты, для какой работы,
  источник (форма или файл). **В строке нет сотрудника.** Есть только название его отдела и псевдоним:
  HMAC-SHA256 от «компания/сотрудник» с ключом сервера `costguard.cabinet.pseudonym-key`
  (`CABINET_PSEUDONYM_KEY`, по умолчанию `CONNECTIONS_ENCRYPTION_KEY`). По псевдониму автор видит и удаляет свои
  сообщения, а по базе без ключа автора не найти.
- Категория определяется по названию: ИИ (провайдеры из `KnownServices`), дизайн, разработка, общение и встречи,
  документы и заметки, хранение файлов, безопасность и доступ, задачи и проекты, «сервисы по подписке», «другое».
- Ввод: форма (`POST /api/v1/me/shadow-spend`) или .xlsx/.csv (сервис, сумма, дата, назначение) тем же разбором,
  что ведомость зарплаты (ADR 0054).
- Сводка (`GET /api/v1/shadow-spend/summary`; owner, finance, it_admin) за 12 месяцев. Сервис показывается, если
  о нём сообщили **не меньше трёх разных людей** (k-анонимность по псевдонимам, строже, чем «три сообщения»: один
  человек тремя сообщениями сервис не откроет). Отдел показывается отдельно, только если в нём трое и больше,
  остальные складываются в «другие отделы». Сервисы ниже порога только считаются, их названия не показываются.
  Назначения трат в сводку не попадают: их текст может выдать автора.
- Фронтенд: вкладка кабинета «Свои траты»; «Запросы сотрудников» → «Свои траты сотрудников».

## Последствия

- Ключ псевдонимов нельзя менять. Новый ключ не найдёт старые сообщения авторов: они останутся в сводке, но автор
  не увидит и не удалит их. Если ключ всё же сменили — старые сообщения удаляются по сроку.
- В маленьком отделе (из трёх человек) отдел почти выдаёт автора даже при пороге. Поэтому отдел показывается, только
  если из него сообщили трое.
- При удалении данных сотрудника его сообщения находятся по псевдониму и удаляются.
